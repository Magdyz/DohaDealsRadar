## Data safety form — answers

Play Console → App content → Data safety. Answer exactly this:

**Does your app collect or share any of the required user data types?** → Yes
**Is all of the user data collected by your app encrypted in transit?** → Yes
**Do you provide a way for users to request that their data is deleted?** → Yes
(URL not needed: deletion is in-app, Account → Delete my account)

| Data type | Collected | Shared | Required? | Purpose |
|---|---|---|---|---|
| Email address | Yes | No | Required | Account management (Google sign-in; held by the sign-in service, never stored in the app's own database) |
| User IDs | Yes | No | Required | Account management, app functionality |
| Name (username) | Yes | No | Required | Account management, app functionality |
| Photos | Yes | No | Optional | App functionality (the deal photo you post) |
| Other user-generated content (deal text, link, prices) | Yes | No | Optional | App functionality |
| App interactions (votes, reports) | Yes | No | Optional | App functionality, fraud prevention & security, analytics (the admin Community Stats screen counts them) |
| Device or other IDs | Yes | No | Required | Fraud prevention and abuse detection |

Everything else → **No**. In particular answer **No** to: location (precise or
approximate), contacts, financial info, health, messages, calendar, files,
search history, installed apps, advertising ID, and crash/diagnostics sharing
with third parties.

Note on "Device or other IDs": the app stores a random ID for the install and
the Firebase messaging token. Both are used only for rate limiting, abuse
prevention and delivering the notifications the user turned on.

## Uploading the update

1. **Check the version.** The build is `versionCode 25`, `versionName 2.0.0`;
   the last Doha release was 24. If Play Console shows a higher number than 24
   in *Production → Releases*, tell me and I'll bump it — an upload with a
   version code that is already used is rejected.

2. **Build the signed bundle** in Android Studio:
   **Build → Generate Signed App Bundle / APK → Android App Bundle → Next**,
   choose your existing **upload keystore** (the same one used for the Doha
   releases), enter the passwords, pick the **release** variant, Finish.
   The file lands in `app/release/app-release.aab`.
   - If Studio ever refuses because it can't find the keystore, that keystore is
     the one thing that cannot be recreated. If it is lost, Play Console →
     *App signing* → *Request upload key reset* is the way back.

3. **Play Console → Test and release → Production → Create new release** →
   upload the `.aab` → paste the *What's new* text (English and Arabic).

4. **Store listing** (Grow → Store presence → Main store listing): replace the
   short and full descriptions, upload the screenshots and the feature graphic.
   Do the same under the Arabic listing, adding العربية as a language if it is
   not there yet.

5. **App content:** update *Privacy policy* with
   `https://magdyz.github.io/DohaDealsRadar/privacy-policy.html`, then redo the
   **Data safety** form with the answers above (it changed: no more analytics,
   no advertising ID).

6. Submit. Review for an update is usually hours to a couple of days.

Do not put "Doha" or "Qatar" anywhere in the listing, screenshots or graphics.
